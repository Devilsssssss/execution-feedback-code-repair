# Execution-Feedback Code Repair

## 5 分钟版本

这是一个关于“小模型是否真的会用执行反馈修复代码”的可复核实验项目。系统把单函数 Python 错误放进隔离执行器：公开测试只用于生成反馈，隐藏测试只在最终评分时运行。每个训练样本都保留任务级划分、错误变异来源、公开失败记录和参考实现，避免把隐藏答案泄露给模型。

## 我做了什么

- 构建 AST 可追踪的边界、逻辑和运行时错误，并加入经过执行审计的模型生成错误；
- 用 Docker/Bubblewrap 隔离不可信代码，记录逐例 repair trajectory；
- 设计 AST-only 与 Mixed 的等规模对照，补齐 297 条 AST 逻辑错误；
- 完成 Qwen2.5-Coder-0.5B QLoRA 训练、HumanEvalFix 143 例评测、反馈消融、反馈置乱和多 seed 复验；
- 发现并记录负结果：旧 Mixed seed42 的提升没有被新 seed 稳定复现，结构化反馈也没有稳定超过无反馈；
- 已冻结一个单变量 feedback-contract SFT：让 completion 显式引用真实失败摘要，检验 SFT 目标是否是反馈利用失败的根因；v3 数据审计已通过，远端训练和评测仍待完成。

## 主要结果

历史 Mixed seed42 在 HumanEvalFix 上为无反馈 72/143、结构化反馈 71/143；精确 AST-only seed42 为 57/143、55/143；Mixed seed43/44 为 61/143、64/143（无反馈）和 64/143、65/143（结构化反馈）。这些结果支持“真实模型错误让训练分布更接近外部错误”，但不支持“反馈已经带来稳定收益”。

## 可信边界

HumanEvalFix 在开发阶段已经被查看，36 例集是追溯冻结确认集，不是历史盲测。通过当前公开和隐藏测试不等于形式化正确；所有结果都应按任务级配对统计，并保留失败轨迹。项目的价值在于实验设计、审计、隔离执行和对负结果的诚实归因，而不是只展示最高分。
